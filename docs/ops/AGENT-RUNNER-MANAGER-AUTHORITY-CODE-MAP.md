# Manager authority: fast code map

Issue: `TheTekTeam/agent-runner#145`

Use this page when a task mentions any of the following:

- manager preflight packet;
- packet revision or fingerprint;
- packet body digest;
- manager authority key;
- approved repository, branch or base commit;
- issue selection based on manager authority.

## The important distinction

**There is no live manager-packet generation method in this repository.**

That is intentional. A canonical packet may be authored only by a normal ChatGPT manager session or an approved ChatGPT scheduled task. The runner and implementation workers consume and validate existing packets; they must not create, refresh or replace manager authority.

Do not spend time searching for a packet generator. Adding an automatic or worker-callable generator would violate the authority boundary documented in [`AGENT-RUNNER-DISPATCH-AUTHORITY-MIGRATION.md`](./AGENT-RUNNER-DISPATCH-AUTHORITY-MIGRATION.md).

## Fingerprint, body digest and authority key

These values have different jobs:

### `fingerprint`

- Supplied by the authorised manager in the YAML packet.
- Must match `sha256:<64 lowercase hexadecimal characters>`.
- Used with the immutable revision to identify one manager authorisation.
- The runner currently validates its shape; it does not derive or recompute it from packet fields.

### `packetDigest`

- Computed by the runner with `packetBodyDigest(body)`.
- SHA-256 of the complete GitHub comment body, including the marker, YAML and surrounding prose.
- Detects an edit to the packet comment even when revision and fingerprint are unchanged.

### `authorityKey`

- Computed by `managerAuthorityKey(revision, fingerprint)`.
- Stable form: `manager-preflight:<revision>:<fingerprint>`.
- Used for claim identity and duplicate-consumption checks.

A new claim therefore depends on both the manager-owned identity (`revision` + `fingerprint`) and the runner-computed unchanged-body evidence (`packetDigest`).

## Fetching issue context efficiently

GitHub issues and pull requests are authoritative. For a known issue, fetch only that issue and its comments first; do not list or read the full queue.

```bash
gh issue view ISSUE_NUMBER --repo OWNER/REPO \
  --json number,title,state,body,labels,assignees,url

gh api --paginate repos/OWNER/REPO/issues/ISSUE_NUMBER/comments
```

Then locate the canonical marker:

```text
<!-- agent-runner:manager-preflight -->
```

The latest valid canonical packet is determined by `resolveCurrentManagerAuthority()`, not by an old proceed command, a historical runner-start comment or comment ID alone.

## Do not change these boundaries casually

Manager-authority changes affect claim safety and require the repository's thorough validation path. Preserve all of the following unless an approved issue explicitly changes the contract:

- only authorised manager producers may author packets;
- the runner never generates manager authority;
- revision and fingerprint remain immutable claim identity;
- body digest detects post-authorisation edits;
- repository, branch and base commit fail closed;
- consumed packets are never reused;
- no claim, GitHub mutation, workspace mutation or model call occurs before authority validation.
